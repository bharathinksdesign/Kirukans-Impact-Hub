Use these steps to locate the middleware returning 403 in your Node.js project.

1. Find the application entry file
Open package.json and check the scripts section:


Copy
{
  "scripts": {
    "start": "node server.js"
  }
}
The file after node is usually the entry file. Common names are:


Copy
server.js
app.js
index.js
src/server.js
src/app.js
If the start command uses another framework, inspect that command as well.

2. Search the entire project for 403 responses
From the project root, run:


Copy
grep -RInE "403|Forbidden|status\(403\)|sendStatus\(403\)|statusCode.?=.?403" \
  --exclude-dir=node_modules \
  --exclude-dir=.git .
On Windows PowerShell:


Copy
Get-ChildItem -Recurse -File |
  Where-Object { $_.FullName -notmatch '\\(node_modules|\.git)\\' } |
  Select-String -Pattern '403|Forbidden|status\(403\)|sendStatus\(403\)|statusCode.?=.?403'
Look for patterns such as:


Copy
return res.status(403).json({ error: 'Forbidden' });

Copy
res.sendStatus(403);

Copy
if (!allowed) {
  return res.status(403).end();
}
3. Search for middleware that may indirectly deny requests
Search for access-control and authentication logic:


Copy
grep -RInE "middleware|isAuthenticated|isAuthorized|authorize|permission|role|allowlist|denylist|whitelist|blacklist|blocked|ip|user-agent|origin|referer|host|maintenance" \
  --exclude-dir=node_modules \
  --exclude-dir=.git .
Pay particular attention to middleware registered before the homepage route:


Copy
app.use(authMiddleware);
app.use(ipFilter);
app.use('/', routes);
The middleware may return 403 without containing the exact text 403, for example:


Copy
if (!req.user) {
  return res.end();
}
4. Check the root route and middleware order
In your entry file, locate the / route:


Copy
app.get('/', ...)
Then inspect every app.use() or router middleware above it:


Copy
app.use('/api', apiRouter);
app.use(authMiddleware);
app.use('/', pageRouter);
For Express, middleware must either send a response or call next():


Copy
function checkAccess(req, res, next) {
  if (someCondition) {
    return res.status(403).send('Forbidden');
  }

  next();
}
A common mistake is an overly broad condition:


Copy
if (req.headers.host !== 'localhost:3000') {
  return res.status(403).send('Forbidden');
}
This would deny the production hostname.

5. Add temporary request tracing
Add this near the top of your main server file, before the suspected middleware and routes:


Copy
app.use((req, res, next) => {
  const originalStatus = res.status.bind(res);

  res.status = (code) => {
    if (code === 403) {
      console.error('403 generated by request:', {
        method: req.method,
        url: req.originalUrl,
        host: req.headers.host,
        userAgent: req.headers['user-agent'],
        forwardedFor: req.headers['x-forwarded-for']
      });
    }

    return originalStatus(code);
  };

  res.on('finish', () => {
    if (res.statusCode === 403) {
      console.error('403 response completed:', {
        method: req.method,
        url: req.originalUrl,
        status: res.statusCode
      });
    }
  });

  next();
});
Also add a simple request log before all routes:


Copy
app.use((req, res, next) => {
  console.log('Incoming request:', req.method, req.originalUrl);
  next();
});
Run the project locally:


Copy
npm install
npm start
Then test the homepage:


Copy
curl -i http://localhost:3000/
If the response is 403, the rule is inside your application. If the local response is 200 but production is 403, inspect production environment variables and proxy-related logic.

6. Check environment variables
Compare your local and Hostinger environment variables. Search for variables that may control access:


Copy
grep -RInE "process\.env\.(ALLOW|DENY|BLOCK|AUTH|ADMIN|IP|HOST|DOMAIN|MAINTENANCE|ENV)" \
  --exclude-dir=node_modules \
  --exclude-dir=.git .
Typical examples:


Copy
if (process.env.MAINTENANCE_MODE === 'true') {
  return res.status(403).send('Forbidden');
}

Copy
const allowedHosts = process.env.ALLOWED_HOSTS.split(',');

Copy
if (!process.env.PUBLIC_URL.includes(req.headers.host)) {
  return res.status(403).end();
}
Check especially:


Copy
NODE_ENV
PORT
HOST
PUBLIC_URL
ALLOWED_HOSTS
ALLOWED_ORIGINS
MAINTENANCE_MODE
AUTH_REQUIRED
TRUST_PROXY
7. Check proxy and host handling
Because Hostinger places the Node.js app behind a proxy, avoid rejecting requests based on a hardcoded local host or port.

Problematic:


Copy
if (req.hostname !== 'localhost') {
  return res.status(403).send('Forbidden');
}
Problematic:


Copy
if (req.headers.host !== 'localhost:3000') {
  return res.status(403).end();
}
Use an allowlist that includes the production hostname:


Copy
const allowedHosts = new Set([
  'kirukans.com',
  'www.kirukans.com',
  'localhost',
  '127.0.0.1'
]);

if (!allowedHosts.has(req.hostname)) {
  return res.status(403).send('Forbidden');
}
Do not rely on the port in Host, because the production proxy may remove or change it.

8. Check static-file and framework configuration
Search configuration files for deny rules:


Copy
find . -maxdepth 3 -type f \( \
  -name '.htaccess' -o \
  -name 'nginx.conf' -o \
  -name 'vercel.json' -o \
  -name 'next.config.*' -o \
  -name 'vite.config.*' -o \
  -name 'webpack.config.*' \
\) -print
Then search them:


Copy
grep -RInE "deny|forbidden|403|redirect|headers|rewrite|middleware" \
  --exclude-dir=node_modules .
For Next.js, inspect:


Copy
middleware.js
middleware.ts
next.config.js
next.config.mjs
For Express, inspect:


Copy
server.js
app.js
routes/
middleware/
9. Remove or correct the rule
Once you identify the middleware, either remove the restriction or narrow it. For example:


Copy
// Too broad
if (req.path === '/') {
  return res.status(403).end();
}
Change it to:


Copy
if (req.path.startsWith('/admin') && !req.user?.isAdmin) {
  return res.status(403).send('Forbidden');
}
Make sure allowed requests call:


Copy
next();
10. Test before redeploying
Run:


Copy
npm test
npm start
curl -i http://localhost:3000/
curl -i http://localhost:3000/health
If your app does not have a health route, temporarily add:


Copy
app.get('/health', (req, res) => {
  res.status(200).send('OK');
});
Then redeploy the corrected project and remove the temporary request-tracing middleware afterward.
